# agy-local-manager

**Экспериментальный пользовательский установщик и восстановитель Antigravity CLI + Ollama для Arch Linux.**

Цель: запускать привычной командой **`agy`** без ручного `AGY_BIN=...`, без редактирования `/usr/bin/agy` и `/usr/lib/node_modules`, с диагностикой и откатом. Проект **не является продуктом Google** и не гарантирует обход ограничений сервиса или стабильную работу после обновлений.

> Статус: **0.1.3 / experimental**. Основывается на подтверждённой локальной конфигурации `agy 1.5.9–1.5.10`, `free-antigravity-cli 1.1.5`, Ollama и GGUF Gemma 4 12B. Полный автоматический сценарий на чужом компьютере не испытан. Не используйте с конфиденциальными рабочими проектами.

## Быстрый старт (Arch Linux / Zsh)

```bash
sudo pacman -S --needed python nodejs npm git curl
paru -S antigravity-cli
# установлен Ollama и предварительно загружена локальная модель

git clone https://github.com/elmarl0w/agy-local-manager.git
cd agy-local-manager
./install.sh
exec zsh
agy doctor
agy setup-model  # пропустить, если модель уже добавлена через free-antigravity-cli
agy
```

Для скачанного архива достаточно выполнить `./install.sh` в распакованном каталоге. Архив может содержать изменения, ещё не опубликованные на GitHub.

`agy` без аргументов запускает пользовательскую копию Antigravity через адаптер. `agy doctor` проверяет компоненты. `agy repair` заново устанавливает закреплённую версию адаптера, восстанавливает патч совместимости и рабочую копию CLI. `agy setup-model` запускает интерактивный мастер моделей. `agy models list` передаёт управление адаптеру. `agy version` показывает версию менеджера.

### Как модель добавляется

В `agy setup-model` выберите **ollama**, укажите **точное имя из `ollama list`** (не SHA/ID), URL `http://127.0.0.1:11434/v1/chat/completions`. По умолчанию локальная Ollama API-ключа не требует (если мастер заставляет, используйте несекретную заглушку). Для нашего случая:

```text
hf.co/google/gemma-4-12B-it-qat-q4_0-gguf:Q4_0
```

Запуск агента может по-прежнему требовать авторизации Google на уровне Antigravity. Патчер локальной проверки не предоставляет серверные права и **не превращает приложение в полностью офлайн-клиент**.

## Архитектура

```text
~/.local/bin/agy                     # пользовательская команда в PATH
    └── agy_manager.py               # версия, состояние, восстановление
        ├── ~/.local/share/agy-local-manager/bin/agy-upstream  # копия /usr/bin/agy
        │      └── локальный совместимый патч (от стороннего проекта)
        └── isolated npm adapter 1.1.5
             ├── local proxy :50998
             ├── исправления схем инструментов
             └── Ollama API :11434 → локальная Gemma
```

Никакие бинарники Google, исходники сторонних проектов, пользовательские аккаунты, OAuth-токены или модели не входят в этот репозиторий. Во время установки компоненты скачиваются из первоисточников; контролируйте доверие к ним.

## Что исправлено

В пользовательской копии `free-antigravity-cli 1.1.5` адаптируются параметры некоторых инструментов для замеченной версии `agy`:

| Вызов | Было | Стало |
| --- | --- | --- |
| `run_command` | `ToolSummary` | `toolSummary` |
| `write_file` | `AbsolutePath` | `Path` |
| `read_file` | `AbsolutePath` | `Path` |
| `run_command` (Bash) | `Cwd` (запрещён схемой) | удаляется; используйте абсолютные пути или `cd` внутри команды |
| `ls`, `cat`, `grep` | преобразование в отсутствующие `list_dir`, `view_file`, `grep_search` | сохраняются в `run_command` |
| HTTP-запрос Ollama | 120 секунд бездействия | 600 секунд по умолчанию (если `model.timeout` не задан) |

Изменения применяются только в изолированной версии адаптера 1.1.5. `agy repair` восстанавливает их после переустановки. Поскольку преобразование shell-команд отключено, для выполнения в другой директории используйте `cd /путь && команда` или абсолютные пути. `model.timeout`, если явно установлен, имеет приоритет над значением 600000 мс.

**Не поддерживается универсальное переименование параметров всех инструментов.** Следующие ошибки требуют нового теста и отдельного исправления.

## Диагностика, обновления и восстановление

```bash
agy doctor
agy repair
agy models list
ollama list
ollama ps
```

На каждом запуске менеджер сравнивает SHA-256 системного `/usr/bin/agy` с последним синхронизированным источником. При обновлении AUR-копии создаётся новая **пользовательская** копия и повторно проверяется совместимость. Если сигнатура локального патчера неизвестна или файл занят работающим процессом, операция **останавливается с ошибкой**, а не перезаписывает бинарник вслепую.

`agy repair` переустанавливает локальную копию адаптера именно версии `1.1.5` и повторно применяет патч с проверкой структуры исходника. Патчер совместимости Google CLI скачивается при первом запуске `repair`, не обновляется автоматически: это осознанное ограничение, чтобы новые коммиты незаметно не меняли код, запускающийся на компьютере.

Чтобы явно обновить внешний патчер, сначала изучите его изменения, затем выполните `git -C ~/.local/share/agy-local-manager/eligibility-patcher pull --ff-only` и `agy repair`.

**Важно:** адаптер или сам CLI может изменять свою пользовательскую копию при запуске. В таком случае менеджер снова проверит её состояние при следующем запуске. Для воспроизводимости не запускайте одновременно несколько экземпляров `agy` на этапе обновления.

## Проверка инструментов

```bash
mkdir -p ~/antigravity-test
cd ~/antigravity-test
agy
```

В агенте попросите создать `test.txt` с содержимым `TOOL_CALL_OK` и прочитать его. Затем **в обычном терминале**:

```bash
cat ~/antigravity-test/test.txt
```

Ответ агента «файл создан» сам по себе не является подтверждением: нужен файл на диске.

## Безопасность

- Версии локального адаптера закреплены; код, скачиваемый из npm и GitHub, всё равно необходимо проверять.
- Команда `agy` запускается без `sudo`. Системный CLI `/usr/bin/agy` не меняется.
- Патч проверки доступности изменяет **только пользовательскую копию** и не гарантирует доступ к Google API. Используйте только в соответствии с условиями доступа к сервису.
- **Не запускайте адаптер версии 1.1.5 с `--debug` при подключённом Google-аккаунте:** в предыдущих тестах он выводил заголовки `Authorization: Bearer ...`. Не публикуйте такие логи. Ранее раскрытые токены необходимо отозвать через настройки Google.
- Не коммитьте `~/.free-antigravity`, `~/.config/antigravity`, файлы авторизации, логи, бинарники и модели. `.gitignore` это исключает лишь в пределах данного репозитория.
- Менеджер не отключает защиту инструментов, не принимает автоматически подтверждения опасных команд и не назначает доступ к чужим рабочим каталогам.

## Удаление

```bash
./uninstall.sh
```

Удаляет только пользовательский менеджер после подтверждения. Не удаляет AUR-пакет, Ollama, Gemma, пользовательские модели или авторизации Google.

## Ограничения

- Linux x86_64 + Arch/paru является основной целевой платформой.
- Зависимость от нестабильного бинарного патчинга; при новом `agy` возможна несовместимость.
- Порт 50998 должен быть свободен, Ollama обычно слушает на 11434.
- Локальные модели отличаются качеством вызова инструментов. Даже корректный `tool_calls` не гарантирует выполнения команды агентом.
- Глобальный `AGY_BIN` больше вводить не нужно: обёртка задаёт его процессу сама.
- `agy doctor` не печатает токены и не проверяет права Google-аккаунта.

## Создание репозитория GitHub

Если репозиторий ещё не создан, можно опубликовать исходники **в приватный GitHub-репозиторий**:

```bash
sudo pacman -S --needed github-cli
gh auth login
./scripts/publish-github.sh agy-local-manager
```

Скрипт инициализирует Git, коммитит **только перечисленные исходные файлы** (allowlist), создаёт приватный репозиторий и пушит `main`. Если `origin` уже есть, скрипт не создаёт и не перезаписывает другой репозиторий. Перед публикацией в открытый доступ проверьте исходники и лицензионные ограничения сторонних компонентов.

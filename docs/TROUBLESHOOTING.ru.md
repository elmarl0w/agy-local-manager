# Диагностика

## `command -v agy` всё ещё `/usr/bin/agy`

Добавить `export PATH="$HOME/.local/bin:$PATH"` в `~/.zshrc` выше других переопределений, выполнить `exec zsh`, проверить `type -a agy`.

## `Text file busy` при repair

Закрыть все сессии Antigravity, проверить `fuser -v ~/.local/share/agy-local-manager/bin/agy-upstream`; не завершать процессы вслепую. Затем `agy repair`.

## Eligibility Check снова появился

`agy doctor` покажет статус патча. Причина может быть в обновлении CLI или серверной проверке. Локальное исправление не гарантирует разрешения доступа Google и не создаёт entitlement. Если версия не распознана, исследуйте проблему вручную, не применяйте force-патчи.

## `Read`: `AbsolutePath not allowed`

Запущена версия без исправленной нормализации. Проверьте `agy doctor`, затем `agy repair`. Убедитесь, что запуск идёт через `~/.local/bin/agy`, а не через глобальный `antigravity`.

## `Create`: `missing property 'Path'`

Та же причина; тестировать `agy repair`. Не подменяйте `AbsolutePath` глобально во всём адаптере.

## `Bash`: `missing property 'toolSummary'`

Адаптер отправляет `ToolSummary` с неправильным регистром. Исправленная версия должна преобразовать поле. Убедитесь, что `agy doctor` видит рабочий adapter.

## `Model unavailable`

Проверьте, работает ли локальный прокси (`ss -ltnp | grep 50998`) и Ollama (`curl http://127.0.0.1:11434/api/version`). Убедитесь, что имя модели в конфиге полностью совпадает с `ollama list`. Запустите запрос к Ollama API напрямую. Не используйте debug с авторизацией.

## `context length exceeded`

Посмотрите `ollama ps` и `systemctl show ollama -p Environment`. Для кодовых агентов 4096 токенов обычно недостаточно, но большие значения требуют RAM и VRAM. Регулируйте `OLLAMA_CONTEXT_LENGTH` на стороне сервиса Ollama, не в этом менеджере.

## Модель отвечает, но файл не создан

Проверка `tool_calls` не выполняет инструмент автоматически. В интерфейсе раскройте вызовы и ошибки. Проверяйте `cat test.txt` в обычном терминале. Ошибки валидации схем инструмента требуют отдельного теста.

## Безопасность

Обычная версия `free-antigravity-cli 1.1.5` может печатать заголовок `Authorization` при `--debug`. Не публикуйте такие логи. Если секрет уже раскрыт, отзовите соответствующую авторизацию Google. Менеджер не сохраняет токены и не выводит их.


## Ошибки `unknown tool: list_dir` и `additional properties Cwd`

В версии 0.1.3 отключено небезопасное перенаправление обычных Bash-команд `ls`, `cat`, `grep` в несуществующие инструменты. Поле `Cwd` удаляется для `run_command`. Обновите проект через `./install.sh` (после закрытия `agy`), затем проверьте `agy doctor`. Для выбора рабочей директории используйте `cd /путь && команда` или абсолютные пути.

## `socket hang up` после ~120 секунд

`free-antigravity-cli@1.1.5` содержит `model.timeout || 120000` в `dist/proxy.js`. Менеджер заменяет значение по умолчанию на 600000 мс при `agy repair`; это тайм-аут бездействия, а не гарантия полного ответа за десять минут. Явно заданное `model.timeout` перекрывает его. Если соединение обрывается, проверяйте `journalctl -u ollama` и настройки модели; не отключайте диагностику ошибок.

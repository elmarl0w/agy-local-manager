# Архитектура и операции

## Почему нужен менеджер

Исходная рабочая конфигурация использовала `AGY_BIN=... node .../cli.js` и два патча. После обновления `agy 1.5.9 → 1.5.10` экспериментальный бинарник оказался без локального патча. Менеджер решает две задачи: одна привычная команда и детектирование drift.

## Дерево

```text
~/.local/bin/agy                               # launcher wrapper
~/.local/share/agy-local-manager/
  app/agy_manager.py
  app/scripts/patch_adapter.py
  bin/agy-upstream                            # пользовательская копия
  npm/node_modules/free-antigravity-cli/      # изолированная версия 1.1.5
  eligibility-patcher/                        # внешняя git-копия
  state/source.sha256                         # fingerprint системного бинарника
~/.free-antigravity/models.json               # не управляется репозиторием
/usr/bin/agy                                  # принадлежит pacman/AUR
```

## Жизненный цикл

1. `agy` читает `/usr/bin/agy` и SHA-256, сравнивает с сохранённым fingerprint.
2. При новом источнике копирует файл в пользовательский каталог, не патчит работающие бинарники.
3. Проверяет состояние локального патча через `manager.py status`; если нужно, применяет только к копии.
4. Проверяет `utils.js` smoke-тестом аргументов инструментов.
5. Запускает локальную Node.js обёртку с внутренним `AGY_BIN`. Пользователь переменные не вводит.
6. Обёртка запускает proxy и дочерний CLI. Возвращает управление терминалу.

## Особенности tool calling

Antigravity 1.5.x проверяет аргументы строго и с учётом регистра. Наблюдались ошибки `ToolSummary` vs `toolSummary` и `AbsolutePath` vs `Path`. Патч адаптера касается только `run_command`, `read_file`, `write_file` и перевода перенаправления shell в запись файла. Нельзя автоматически заменять все пути: для других инструментов могут быть иные схемы. Задачи агента необходимо проверять на диске.

## Обновления и отказоустойчивость

- При обновлении AUR синхронизируется пользовательская копия. При отсутствии поддерживаемой сигнатуры программа останавливается.
- При повреждённом npm-адаптере `agy repair` заново устанавливает зафиксированную версию.
- При занятом бинарнике repair останавливается. Не применяется автоматический `kill -9`.
- Компоненты обновляются **не атомарно** как единая система: запуск каждого нового бинарника нужно повторно проверять smoke-тестами.
- Для production нужна верификация контрольных сумм исходных артефактов и независимый аудит патчеров.

## Поверхность доверия

Исполняются сторонний npm-пакет, патчер из GitHub, оригинальный `agy` и Ollama. Устаревший адаптер печатал OAuth-токены в debug. В репозиторий не включаются cookies, конфигурация аккаунта, токены, клиентские данные. Debug по умолчанию не включается.

## Что нельзя гарантировать

Наличие локального патча не создаёт серверных прав Google, не отменяет правила сервиса и не гарантирует офлайн-режим. Состояние модели и ответ API Ollama не подтверждают автоматически успешную запись файла; проверяйте результат отдельной командой.
